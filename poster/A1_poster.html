Wireless Intrusion Detection System

A Random Forest prototype for detecting Wi-Fi deauthentication floods

WIDS prototype
offline replay

Why this matters

A deauthentication flood sends repeated management frames that can disconnect wireless clients. This project demonstrates a safe, explainable detector using labelled AWID3 traffic. It raises an alert; it does not attack a network, capture live traffic, or block devices.

Research question

Can simple radio and traffic-rate features distinguish normal Wi-Fi traffic from deauthentication attack traffic on previously unseen capture files?

Objective

  • Use a small, reproducible public-data workflow.
  • Detect deauthentication traffic.
  • Report accuracy, recall and a confusion matrix.
  • Provide a dashboard demonstration.

System workflow

1. InputAWID3 CSV capture files
2. FeaturesLength, timing, signal, reason code and one-second device rates
3. ModelsBehavioural detector plus protocol-feature baseline
4. DecisionThreshold selected on validation captures
5. AlertConfidence-ranked offline replay alert in dashboard

Safety boundary

WIDS, not WIPS: response actions are disabled. Any future live capture or attack generation must use an authorised isolated lab network.

The prototype uses stored test-set predictions so the demonstration is repeatable and safe.

Evaluation design

Complete capture files, rather than random rows, define the split to reduce leakage.

PurposeFilesUse
TrainingDeauth_0 to Deauth_24Fit the classifier
ValidationDeauth_25 to Deauth_28Select alert threshold
Final testDeauth_29 to Deauth_32Report final performance

The behavioural detector excludes frame type and subtype. A protocol-feature baseline includes them for comparison because they are highly informative in AWID3.
